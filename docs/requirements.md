# 需求文档 (Requirements Document)

## 1. 引言

### 1.1 项目背景
随着 Kubernetes (K8s) 集群规模的日益增长，运维复杂度也随之上升。为了快速感知集群状态、定位问题并获取修复建议，本项目旨在开发一个基于 Eino 框架 (Golang) 的智能分析 Agent —— "K8s Analyzer Agent"。该 Agent 将通过集成现有的 MCP (Model Context Protocol) 工具，实现自动化的信息收集、安全的命令执行以及智能化的诊断分析。

### 1.2 项目目标
构建一个智能 Agent，能够：
1.  自动获取 K8s 集群的核心状态信息。
2.  在严格的安全控制下执行必要的 Shell 诊断命令。
3.  综合各类信息，生成包含状态概览、异常诊断及修复建议的分析报告。

## 2. 功能需求

### 2.1 K8s 信息获取
- **功能描述**：Agent 需通过集成 `github.com/AceDarkknight/k8s-mcp` 提供的客户端库或直接连接其 Server，与 K8s API Server 交互，获取集群资源信息。
- **具体要求**：
    - 支持获取 Node 状态（CPU/内存使用率、Ready 状态等）。
    - 支持获取 Pod 状态（Running, Pending, CrashLoopBackOff 等）。
    - 支持获取 Deployment, Service, ConfigMap 等常见资源信息。
    - 支持通过 Label Selector 过滤特定应用或命名空间的资源。

### 2.2 安全命令执行子 Agent
- **功能描述**：为了执行一些非 K8s API 原生支持的诊断操作（如网络连通性测试、日志文件查看等），系统需集成 `github.com/AceDarkknight/shell-executor-mcp`。为了防止误操作或恶意破坏，必须封装一个独立的子 Agent 负责命令的安全评估与执行。
- **具体流程**：
    1.  **请求接收**：主 Agent 向子 Agent 发送待执行的 Shell 命令。
    2.  **安全评估**：子 Agent 首先对命令进行语义分析和安全检查。
        - **只读性检查**：确保命令不会修改系统状态（如禁止 `rm`, `mv`, `chmod`, `> ` 重定向写入等）。
        - **安全性检查**：禁止执行敏感命令（如涉及密钥读取、提权操作等）。
    3.  **命令执行**：只有通过安全评估的命令，才会被转发给 `shell-executor-mcp` 执行。
    4.  **结果返回**：执行成功返回标准输出；执行失败返回标准错误；安全评估未通过返回拒绝原因。

### 2.3 智能分析报告
- **功能描述**：主 Agent 负责汇总 K8s 资源信息和 Shell 命令执行结果，利用 LLM 的能力生成最终报告。
- **具体要求**：
    - **集群状态概览**：总结集群健康度，列出异常节点或组件。
    - **服务状态分析**：针对用户关注的服务，分析其副本数、资源水位、重启次数等。
    - **异常诊断与修复**：
        - 识别具体的异常现象（如 Pod 频繁重启、服务访问超时）。
        - 结合日志和状态信息，推断可能的根因（Root Cause）。
        - 提供具体的修复方案或操作建议（如“建议扩容 Node”、“检查 ConfigMap 配置”等）。
    - **报告格式**：输出清晰易读的 Markdown 格式报告。

### 2.4 动态工具发现
- **功能描述**：Agent 需具备动态发现和集成 MCP 工具的能力，而非依赖硬编码的工具列表。
- **具体要求**：
    - **启动查询**：Agent 在启动初始化阶段，必须向所有配置的 MCP Server 发送 `ListTools` 请求，获取最新的可用工具列表及 Schema。
    - **Prompt 动态注入**：Agent 必须将获取到的工具定义动态注入到 LLM 的 System Prompt 中，确保 LLM 能够感知并使用所有可用工具。
    - **版本适应性**：当 MCP Server 端工具定义变更（如新增参数）时，Agent 无需重新编译，只需重启即可通过新的 Prompt 适应变化。

## 3. 非功能需求

### 3.1 安全性
- **最高优先级**：Shell 命令执行功能必须具备严格的安全围栏。任何可能破坏系统稳定性或泄露敏感数据的命令都应被拦截。
- **最小权限原则**：运行 Agent 的环境应配置适当的 RBAC 权限和 OS 权限。

### 3.2 可扩展性
- 基于 Eino 框架开发，采用图（Graph）结构编排 Agent 逻辑，便于后续添加新的 MCP 工具或分析插件。
- 架构设计应支持未来接入更多的诊断工具。

### 3.3 易用性
- 用户只需提供自然语言描述的问题或检查请求，Agent 自动拆解任务。

### 3.4 健壮性
- **初始化检查**：系统启动时，若无法成功连接 MCP Server 或无法获取工具列表，必须立即报错并终止启动（Fatal Exit），不应在能力缺失的情况下勉强运行。
- **降级保护**：在运行过程中，若工具执行偶尔失败，应有重试机制，但初始化阶段的工具发现失败是致命的。

## 4. 用户交互流程

1.  **用户输入**：用户向 K8s Analyzer Agent 发送指令，例如：“检查 default 命名空间下 nginx 服务的状态，并分析为什么有些 Pod 在重启。”
2.  **任务拆解**：
    - 主 Agent 分析意图，决定需要调用 K8s MCP 获取 Pod 列表和 Events。
    - 主 Agent 决定需要调用子 Agent 执行 `curl` 命令检查 Service IP 连通性，或查看特定日志文件。
3.  **执行与评估**：
    - K8s MCP 返回资源数据。
    - 主 Agent 向子 Agent 发送 `curl` 命令。
    - 子 Agent 评估 `curl` 为安全只读命令，执行并返回结果。
4.  **报告生成**：主 Agent 综合所有数据，生成包含现状、原因和建议的报告。
5.  **输出结果**：展示 Markdown 报告给用户。
