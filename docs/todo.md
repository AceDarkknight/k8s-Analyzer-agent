## 1. 优化 K8sInfo 数据结构以支持更多 K8s 信息

**文件位置**: `internal/agent/analysis/state.go`

**现状问题**:
- 当前 `K8sInfo` 结构体中，`Resources` 字段使用 `map[string][]any` 存储所有 K8s 资源，类型安全性较弱。
- `NetworkInfo` 被单独定义为一个字段，与 `Resources` 的统一存储方式不一致。
- 缺乏对集群级别信息（如 Node、Namespace、ClusterInfo）的统一支持。
- 缺少对资源元数据（如获取时间、来源命名空间）的追踪能力。
- `GetSummary()` 方法仅能输出各类型资源数量，无法展示资源的关键状态信息。

**优化目标**:
- 设计更灵活、类型更安全的资源存储方式，支持按命名空间隔离存储资源。
- 支持集群级别资源（如 Node、Namespace）与命名空间级别资源的统一管理。
- 增加对资源获取时间戳和数据来源的追踪，便于判断数据新鲜度。
- 增强 `GetSummary()` 方法，使其能够包含关键状态信息（如异常 Pod 数量、节点健康状态）。
- 考虑引入泛型或接口约束，提升类型安全性，减少运行时类型断言的风险。

## 2. 优化 ReAct LLM 提示词（Prompt Engineering）

**文件位置**: `internal/agent/analysis/react_llm.go`

**现状问题**:
- **`getReActSystemPrompt()`**: 系统提示词较为简单，对工具调用的约束和指导不够精确，可能导致 LLM 产生幻觉工具名称或参数。
- **`buildDecisionPrompt()`**: 决策提示词中，当前资源状态展示过于简单（仅显示数量），缺乏关键状态信息（如 Pod 的详细错误状态），影响 LLM 决策质量。
- **`buildReActPrompt()`**: 错误分析提示词结构较松散，缺少对 LLM 输出格式的明确约束，导致 `parseReActResponse()` 解析失败率偏高。
- **`buildSynthesizePrompt()`**: 综合报告提示词缺少对报告语言（中文）和专业术语使用的要求。
- **多语言混用**: 部分提示词英文与中文混用，可能造成 LLM 输出语言不一致。

**优化目标**:
- **系统提示词**: 增强角色定义，加入具体的 K8s 故障排查思路（如优先检查资源状态 → 查看日志 → 分析事件），引导 LLM 更系统地思考。
- **决策提示词**: 在当前资源状态展示中，增加 Pod 状态详情（Running/Pending/CrashLoopBackOff 数量）、关键异常信息摘要，帮助 LLM 做出更准确的 continue/report 决策。
- **错误分析提示词**: 明确指定输出必须为 JSON 格式，并在 Prompt 中提供 JSON Schema 示例，降低解析失败率。
- **报告生成提示词**: 统一要求所有输出使用中文，并增加报告质量标准（如：建议必须具体可执行，不能泛泛而谈）。
- **链式思考（Chain-of-Thought）**: 在关键决策和分析 Prompt 中加入 CoT 引导，要求 LLM 先逐步分析数据，再给出结论，提升分析深度和准确性。
